# МОП Reminder Bot — Дизайн-спецификация
_Дата: 2026-05-23_

## Обзор

Расширение существующего Bitrix24 Report Bot: за 10 минут до дедлайна задачи МОП получает в личный Telegram уведомление с данными по клиенту и AI-рекомендацией от Claude на основе последнего звонка и записи визита в ОП.

---

## Архитектура

```
Bitrix24
  ├── Задачи (tasks.task.list)
  │     Фильтр: CREATED_BY = МОП, UF_CRM_TASK содержит D_XXXXX
  │     Триггер: DEADLINE в окне [now+8min, now+13min]
  ├── Активности по сделке (crm.activity.list)
  │     - Последний CALL (приоритет для рекомендации)
  │     - Последний MEETING/VISIT (контекст истории)
  └── Сделка (crm.deal.get)
        - Название, этап, ответственный, кол-во дней в этапе

        ↓ Polling каждые 5 минут (job_queue)

    task_reminder.py
        ↓ Если задача не в reminders_sent

    ai_advisor.py → Claude API
        Системный промпт: эксперт по продажам недвижимости в Алматы
        Вход: транскрипт/резюме звонка (70%) + визита (30%) + данные сделки
        Выход: структурированная рекомендация (3-4 пункта)

        ↓

    Telegram → личный чат МОПа
```

---

## Фильтрация задач

Задача попадает в обработку если выполнены **все** условия:
1. `CREATED_BY` = `bitrix_id` МОПа (МОП сам создал задачу)
2. `UF_CRM_TASK` содержит хотя бы одну ссылку вида `D_XXXXX` (привязана к сделке)
3. `DEADLINE` попадает в окно `[now + 8 мин, now + 13 мин]`
4. `REAL_STATUS != 5` (задача не выполнена)
5. ID задачи отсутствует в таблице `reminders_sent`

```
🔔 Звонок через 10 минут

👤 Клиент: Асель Нурланова
🏠 Сделка: ЖК Керуен, 2к, 65м²

<резюме/транскрипт из Bitrix24 CoPilot или описание активности>

🏢 Визит в ОП (10 дней назад):
<резюме встречи>

🤖 Рекомендация:
• На что обратить внимание: ...

• Как закрыть на следующий шаг: ...
```

Если звонка нет — рекомендация строится только на визите.
Если нет ни того ни другого — Claude даёт рекомендацию на основе данных сделки (этап, срок).

## Компоненты

### `task_reminder.py` (новый файл)
- `check_upcoming_tasks()` — async функция, вызывается job_queue каждые 5 минут
- Для каждого зарегистрированного МОПа: запрашивает задачи в окне дедлайна
- Извлекает deal_id из `UF_CRM_TASK`
- Вызывает `fetch_last_call()` и `fetch_last_visit()` из `bitrix.py`
- Вызывает `get_recommendation()` из `ai_advisor.py`
- Отправляет сообщение в Telegram, записывает в `reminders_sent`

### `ai_advisor.py` (новый файл)
- `get_recommendation(deal, call, visit) -> str`
- Системный промпт: роль эксперта по продажам недвижимости в Алматы, методология ЖК Керуен
- Формирует prompt: звонок (приоритет) + визит (контекст) + данные сделки
- Использует `claude-sonnet-4-6` (баланс скорость/качество)
- Возвращает текст рекомендации 3-4 пункта

### Расширение `bitrix.py`
- `fetch_mop_upcoming_tasks(user_id, window_start, window_end)` — задачи МОПа в окне дедлайна
- `fetch_last_call(deal_id)` — последняя активность типа CALL по сделке
- `fetch_last_visit(deal_id)` — последняя активность типа MEETING по сделке
- `fetch_deal_detail(deal_id)` — название, этап, ответственный, дни в этапе

### Расширение `db.py`
- Таблица `mop_telegram`: `bitrix_id INTEGER, telegram_id INTEGER, name TEXT`
- Таблица `reminders_sent`: `task_id INTEGER, sent_at TEXT` (хранить 7 дней, потом чистить)

### Расширение `bot.py`
- Команда `/mop` (только admin):
  - Шаг 1: показывает список МОПов из Bitrix24
  - Шаг 2: admin вводит Telegram ID выбранного МОПа
  - Шаг 3: сохраняет в `mop_telegram`, подтверждение

## Промпт Claude (системный)

```
Ты — эксперт по продажам первичной недвижимости в Алматы.
Твоя задача — помочь менеджеру подготовиться к звонку с клиентом.

На основе предоставленных данных дай краткую рекомендацию (3-4 пункта):
1. На что обратить внимание в этом звонке
2. Главное возражение или сомнение клиента
3. Конкретный следующий шаг для закрытия сделки

Приоритет: данные последнего звонка (там клиент даёт обратную связь).
Визит — используй как контекст истории отношений с клиентом.

Будь конкретным, практичным, без воды. Максимум 5 предложений.
```

## Ограничения и риски

| Риск | Митигация |
|---|---|
| Тип активности "визит" может называться иначе в Bitrix24 | Исследуем при подключении, сделаем настраиваемым |
| Claude не получит транскрипт если CoPilot не настроен | Fallback на описание (`DESCRIPTION`) активности |
| МОП меняет дедлайн задачи в последний момент | Polling пересчитает в следующем цикле |
| Много МОПов → много API-вызовов | Параллельные запросы через `asyncio.gather` |
